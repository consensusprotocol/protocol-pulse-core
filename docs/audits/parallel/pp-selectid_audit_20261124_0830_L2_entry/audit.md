# Heimdall audit

**Question:** pp-selectid (Protocol Pulse clip-video builder). The verifier found that builds 166-168 ran "by hand": a wrapper script imported tests/package/proof_ledger.py and called main() with patched settings, through the launcher's DRIVER= override. RULING 163 (5): the build record states which driver ran and its git sha, and the launcher refuses any driver that is not the committed one; RULING 160 (2b): one outcome line per build. THE CHANGE (diff below): proof_ledger.main() now (a) refuses (exit 2, no record) unless entry_of() finds sys.modules['__main__'].__file__ is this file (realpath), or pytest with PP_SELECTID_DRIVER_UNDER_TEST=1 (set only by tests/package/conftest.py); _main() (the old body, otherwise unchanged) checks entry_of() again; (b) wraps _main in try/finally and calls outcomes.record_build(out_dir) once when box["out_dir"] was set (right after os.makedirs(out_dir)); SIGTERM -> sys.exit(143) so the finally runs; (c) writes "entry" (driver, driver_sha = git hash-object, driver_committed, argv0, HEAD, dirty files) into inputs.json. The launcher tests/package/record/build_and_record.sh (moved from a scratch folder into git, paths repo-relative) runs only tests/package/proof_ledger.py with --build-no N, and refuses (exit 6) when that driver differs from HEAD, any .py/.sh under pipeline/ or tests/package/ is changed and not committed, or HEAD has commits not pushed.
CHECK, quoting the code: (1) can a wrapper still run a build (through main(), _main(), or the launcher with DRIVER= set), and does a plain `python3 -B tests/package/proof_ledger.py ...` still pass entry_of; (2) can a build that made its record folder end with no outcome line or two (an exception inside record_build, SystemExit, KeyboardInterrupt, a return before box is set); (3) bash bugs in the launcher's new guards (git diff --quiet exit codes, the status/awk/grep pipeline when nothing matches, '@{u}' with no upstream, set -u). Report only what the code shows; if unsure, say so.

**Panel:** qwen27b, gptoss, gemma  |  **Cost:** $0.0396
## Consensus findings (majority of panel agrees)
- **[low] tests/package/proof_ledger.py:515** The finally-block inner handler catches only Exception. If OC.record_build itself raises a BaseException (e.g. SystemExit from a sys.exit inside a helper, or KeyboardInterrupt during the write), it propagates uncaught, no outcome line is written, and the error is not reported to stderr. The outer except BaseException / raise has already re-raised the build's own exception, so the process dies with no RULING 160 (2b) line and no diagnostic.
  - evidence: `            except Exception as e:                       # noqa: BLE001  never masks the build's own end
                print(f"  RULING 160 (2b): the outcome line was NOT written: {type(e).__name__}`
  - fix: Widen the inner handler to except BaseException (or at least except (Exception, SystemExit)) so a failure inside record_build is always reported and never silently swallows the outcome line.
  - raised by qwen27b:F3; agree: qwen27b, gemma
