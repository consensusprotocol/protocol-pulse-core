**N1 (P2) — `hook_ratings`'s `out` mixes cached and fresh records with different shapes.** package.py:283 vs 316. A cached record is `dict(rec, cached=True)` — whatever the cache held, plus `cached`. A fresh record is `{parts, rating, why, backend, rule, cached: False, replayed: ...}`. If a *previous* build cached a record, then the code changed what it stores (e.g. added "rule"), old cache entries lack "rule" while fresh ones have it. Consumers of `out["hook_pool"]["ratings"]` (line 511) see both. `hook_line` (line 370) uses `.get()` throughout, so nothing crashes; but `hook_order` (line 363) does `hr(m).get(k) or 0` — a cached record missing a part sums 0 for it, which could reorder "best" between a cached and a fresh record of equal rating. Concrete: cached `{"scroll":5,"alone":5,"setup":5,"rating":5}` (no parts? no — parts are stored). Actually the fresh record stores all parts, and the cache stores the fresh record, so a *round-tripped* record has all parts. Only a hand-edited or older-versioned cache diverges. HOOK_VERSION pins the prompt, not the record schema — a schema change without a HOOK_VERSION bump would silently mix. P2: recommend documenting that any change to the stored record's shape requires bumping HOOK_VERSION (or the record's own version). Nobody caught this.
