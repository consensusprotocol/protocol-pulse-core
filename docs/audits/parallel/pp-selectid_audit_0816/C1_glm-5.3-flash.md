## Answers to the specific checks requested

- **Match never merges two different speeches that merely share words:** the 80 % in-order bound plus the multiset pre-check (which is a true upper bound on aligned words — shared multiset count ≥ aligned count, since every aligned word is shared) — sound. The pre-check's upper-bound property: `sum((Counter(ta) & Counter(tb)).values())` counts shared *tokens*; any in-order alignment's matched words are a sub-multiset of the shared tokens, so if shared < 0.8×short, aligned < 0.80×short. Proven. ✓
- **Original chosen by publish time, not order:** yes for readable, distinct times; equal readable times → id tie-break via the third tuple element; naive/None → after all aware times, then id. The naive-vs-aware question (P1-1) is the one open item. ✓ (with the caveat)
- **No copy reaches the angle step:** `build()` applies `reposted_once` immediately after `usable()` (line 91), before `no_role`/`trims`/step A; the copy is removed from `ms` before any downstream consumer. The test at line 171-178 asserts the copy is absent from the angle prompt. ✓ (conditional on `Rig` faithfully representing the real angle step — not verifiable from the diff)
- **The recorded reason:** names original id/channel/time, copy channel/time, and the match; the transitive-merge case falls back to "aligned through another copy" (line 79) — but see P2-2: a direct-pair reason may be cited even when the merge was transitive; still a true statement. ✓
- **Slow on 300 moments:** measured 2.3 s at 308; O(n²) with pruning; ~10× at 1000 moments ≈ 23 s. Acceptable for a batch build; not a blocker. ✓
