## SECTION 6: WORLD-CLASS GAP ANALYSIS

**Already excellent (genuinely):** the "rewritten only when it changes" discipline (the line's time is event-derived, never the clock) is the kind of detail Bloomberg-terminal-grade systems get wrong constantly. The once-per-cause error logging, the pid+thread-unique tmp+atomic-replace, the switch-line-first invariant enforced structurally (spend.py:58) rather than by convention, and the defensive `_detail` parsing — this is production-grade hygiene. The test that asserts no test writes the real STATE file (test_cycles.py::test_no_test_writes_the_real_state_file) shows the author has been burned before and learned.

**Material gaps:**
1. **No line-length/entry cap.** A first-sight backfill (40+ videos, watch.py:28) or a busy hour (20 discoveries) produces a line of thousands of characters. Every other notice on STATE is one sentence. The orchestrator reads line 1; a 4,000-char line 1 is a failure of the feature's purpose. (cycles.py:86-101.)
2. **No video title.** "dQw4w9WgXcQ Bitcoin Today" vs "dQw4w9WgXcQ" — the orchestrator said "video"; an id is a hash, not a video. (cycles.py:29, 90.)
3. **The vanish bug (1.1, Bug 6)** — the line disappears exactly when the 09:02 condition is *false but interesting* (Bitcoin was mined, no cycle found anything). A professional would have written the test for this: cycle-quiet + mined-in-window.
4. **No "has anything changed" short-circuit.** Every 60 s, the full compose runs (3 event scans + N+1 point queries) even when the last event ts is unchanged. A 5-line guard (`SELECT MAX(ts) FROM events WHERE kind IN (...)` vs a cached value) would cut 95% of the work. Not needed at this scale, but it's the difference between a hack and a system.
