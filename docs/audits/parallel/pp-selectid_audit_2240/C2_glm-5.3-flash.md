## 3. New findings from this review

**N1 (P2). `no_voice()`'s added-clip candidate can duplicate the hook's channel via `pos`-ordering, not content — verified safe, but the *sort* is subtly load-bearing.** Line 438: `cand = [segs[0]] + sorted(segs[1:] + [m], key=lambda x: pos.get(x["moment_id"], 99))`. If the added moment `m` is not in `angle["moments"]` (it always is — it's drawn from that list, line 433), the `99` default would silently reorder it to the end. It can't happen here (the `for mid in angle["moments"]` loop guarantees `mid in pos`), but the `99` sentinel is dead-code-adjacent: if anyone later draws candidates from `cleared` instead, the new clip silently lands last rather than in the proposer's order, and no test would catch it because `test_no_voice_when_the_takeaway_fails_twice...` adds `z` which *is* last in the angle. A test where the added clip is *first* in the angle's order would pin the sort. P2, latent.

**N2 (P2). `over_budget` reads the meter twice per check and the two reads can straddle a settle.** Lines 404: `est, rep = (a - b for a, b in zip(_spent(spend), usd0))`. `_spent` calls `spend()` once — fine. But `over_budget` is called at line 505 (before the line-up) *and* at 516 (before every write) *and* at 593 (after the angle); between the line-up check and the first write check, the medley call's cost lands. That's correct behavior (the check is *before* the next spend), but note the *last* write's cost is never re-checked before the paid gates run (lines 466–474, 527+): a package's fidelity/context verdicts and the no-voice re-verification can exceed the $1.50 reported budget with no further check. The ruling says "per package 15 min / $1.50"; the gates after the last write are unguarded. In practice the deltas are small (verdicts are cheap), but the wall clock is *not* re-checked there either, and the no-voice path adds a whole second medley call + paid gates. P2: the ruling's "per package" bound is enforced only at write/line-up granularity, not at package-commit granularity. Nobody said this in Cycle 1.

**N3 (P2). `writer_avoid` is computed once, from the *angle's* chain, but `write_takeaway`'s `avoid_vendor` interacts with `Router.call`'s failover: after a deadline failover, the *next* write's avoid-set is stale.** Lines 395–396: `writer_avoid = {vendor for backends in chain} - {angle_reply.vendor}`. If the angle came from heimdall (deepseek), `writer_avoid = {"xai"}` — wait, the chain in the Rig is `["heimdall:deepseek", "heimdall:qwen", "xai:grok"]` and the test at 1255–1260 asserts `write_avoid == [{"heimdall", "xai"}]` because the angle's vendor is "fake". In production, if the angle's vendor is heimdall, `writer_avoid = {"xai"}` and both heimdall backends (deepseek *and* qwen) remain eligible — good, the failover target survives. If the angle's vendor were xai, `writer_avoid = {"heimdall"}` and a heimdall deadline-failover has nowhere to go but xai — which is the angle's vendor, so L-x (the judge avoids the judged) still holds because the *judges* avoid by family, not by this set. Verified consistent. But: `out["angle_tried"]` (line 393) records the *angle* call's failover; the *write* calls' failovers land in each `Reply.tried` inside `write_takeaway`'s returned `wr`, which is recorded... where? `rec["attempts"]` gets `att` (line 528) — I cannot see from this diff whether `wr.tried` is persisted into the attempt record. If it isn't, ruling 5's "the failover is recorded" is satisfied for the angle call but only *transiently* for the writes. **Needs-confirmation; potentially P1** if `att` drops `wr.tried`. (The Rig's `write_calls` records only `(segs, join)` and `avoid_vendor` — not the reply's tried — so no test covers it.)

**N4 (P2). `test_the_budget_stops...`'s `reads`/`calls` iterator (lines 1266–1269) hard-codes the *number* of `_spent` reads.** `reads = [(0,0), (0,0)]` then `calls = iter(reads + [spent]*50)`. If `build()`'s call order changes by even one `over_budget` invocation (e.g. the N2 fix adds a check), the test silently consumes the wrong slot and asserts against `spent` when it's still reading `(0,0)` — it would then *fail* loudly, which is fine, but the 50× padding means it can also *pass* while masking a missing check (a check removed → one fewer read → the iterator still has `spent` left). Padding masks, not pins. P2, test-robustness.

**N5 (P2, confirming glm's withdrawn P0-2 with a twist).** `no_voice()`'s added-clip loop (433–444) checks `m["channel_id"] in chans` where `chans = {m["channel_id"] for m in segs}` — the hook's channel included. Consistent. No finding; recorded so the next auditor doesn't re-derive it.

**N6 (P1→P2, the one nobody priced). `EMOJI_RE`'s hand-rolled range `☀-➿⭐⭕️` (line 39) mixes a literal range with literals, and `⭕️` carries a variation selector (U+FE0F) that the class does not include.** A caption "no ruler ⭕️" — the ⭕ (U+2B55) matches, but the trailing ️ (U+FE0F) is *not* in any class, so `findall` returns `["⭕"]`... actually `findall` on a class returns each matching char; the FE0F is simply not matched and not reported. Result: the violation detail reports `⭕` but the *lint passes* (one match is enough) — no bug. However, a caption consisting of *only* a variation-selector-decorated char where the base char is outside all ranges (e.g. certain keycap sequences) would pass with zero matches. This is a completeness nit, not a correctness bug: the ruling's emoji list is open-ended anyway. P2, cosmetic. I flag it only because the ruling says "no emoji" and the class is provably not exhaustive (no U+FE0F, no keycaps, nothing outside BMP beyond the stated ranges).

**N7 (P2). `recency_problems` accepts `source_published_at` values that `utc_z` would never produce** — e.g. `"2026-02-30T01:00:00Z"` fails `strptime` (caught, line 662–665) — good — but `"2026-11-12T01:00:00Z"`-shaped strings with a *leading/trailing space* fail the regex, good. But the test at 839–841 checks `"2026-11-12T01:00:00+00:00"` is *refused*; that's stricter than ISO 8601 requires, and it's the right call (the ruling says "ISO 8601 UTC" and the seal is canonical). No finding. Recorded.

If the real `paid_gates` requires a takeaway line to judge, the no-voice package fails at line 475–478 with `why_not = "the title / caption fail VO fidelity or context integrity"` — a *misleading* diagnostic for a structural (missing-takeaway) cause.
