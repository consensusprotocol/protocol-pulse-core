## 3. HOW A RENDER RUNS

**For a builder pin (medley or spotlight):** the builder sends the pin path and the seal (its READY line prefix). Then:
1. **12 h check (rulings 76 / 77).** Every segment's `source_published_at` must be within 12 h of now:
   `python3 -c "import json,sys,datetime as d; p=json.load(open(sys.argv[1])); n=d.datetime.now(d.timezone.utc); print([(s['video_id'], round((n-d.datetime.fromisoformat(s['source_published_at'].replace('Z','+00:00'))).total_seconds()/3600,2)) for s in p['segments']])" <pin>`.
   Any value above 12.0: do not render; tell the builder and log it.
2. **Yield GPU0:** `touch /tmp/pulse_gpu0.yield`. The pre-check, scorer and judge yield. Wait until `/tmp/pulse_gpu0.lease` is free.
3. **Freeze** a copy: `cp <pin> data/moments_pins/<NAME>.json`.
4. **Readiness:** `python3 -B scripts/integrator/check_pin_only.py data/moments_pins/<NAME>.json <seal prefix>`.
   - It prints READY or the reason.
   - It runs the builder's `gate_problems`, `trim_problems` and `seal()` from `/home/ultron/worktrees/pp-selectid/pipeline/package_pin.py`.
   - A spotlight seal passes `shape` and `first_comment`.
   - Then main's `pinned.validate_schema` and `moments_vo`.
5. **Launch:** `env -u TMUX bash scripts/pulse_check_run.sh --pinned data/moments_pins/<NAME>.json`.
   - It runs in a detached tmux `pipeline_pulse_check_<UTC>`.
   - Log: `logs/pulse_check/run_<stamp>.log`. Run dir: `runs/pinned_<stamp>/`.
6. **Release the flag:** `rm /tmp/pulse_gpu0.yield` once the render holds the lease.
7. **Report:** when it ends, the DoD's first line is the PASS path with its ids, or HOLD with the stage, the row and the facts. Commit the DoD only after the run. ## 7. KNOWN TRAPS (one line each)

- The pre_bash hook blocks any command whose text holds both "-f" and "push" (`--no-ff`, tag or branch names, prose). Push in a separate command: `BR=$(git rev-parse --abbrev-ref HEAD); git push origin "$BR"`.
- The hook also blocks ".env" substrings, including `os.environ`. Write such Python with the Write tool.
- Test files and `docs/references` are git-ignored: `git add --force` them (never in the same command as a push).
- `git push --tags` would push `pre-lfs-fix-backup`, which is not ours. Push one tag through a glob.
- Worktrees lack untracked data (the references' transcripts, the v2f run files, the outro asset). Run the regressions on main's staged merge.

- The stop hook flags a staged merge as "UNCOMMITTED" while the regressions run. That is expected; commit only after both regressions pass.
- Never move the release-branch HEAD while `/tmp/pulse_check_run.lock` is held by a render (E-FAIL-078). The lock FILE always exists; check `fuser`.
- A long-running process that decodes on GPU0 keeps a CUDA context after release_all, and every other GPU0 user sees a foreign process (E-FAIL-084). Run such work as one-shot processes.
