# Heimdall audit

**Question:** Batch 37 = the REVIEW DROP (orchestrator order 2026-11-12 '13:06'; law L-j unchanged: no file reaches the approver labelled as passed unless a release authorisation binds that verdict to its exact bytes). New code BESIDE the release path (telegram.deliver_run + release_auth.authorise, untouched): telegram.review_drop(run_dir) sends a run that is NOT authorised to the approval chat as an engineering review. Requirements: it REQUIRES the run's GATE_REPORT.json (refuses without); every caption / note is generated by code and begins 'REVIEW ONLY - NOT A PASS - not for publishing', then lists EVERY required row (release_auth.INVENTORY) that is not exactly PASS with a one-line measured reason, the sha256 of each file (exactly the bytes sent), run id, HEAD, title, caption, per-clip source links and deviations; the caller cannot edit or suppress the non-pass list; it refuses any text carrying PASS-as-verdict wording, 'CANDIDATE FOR APPROVAL' or 'approved'; it refuses when a content-integrity row (G16, G17, G12, G15, G20, V1) is not PASS; it refuses a second drop of the same run; it writes REVIEW_DROP.json (what was sent, which chat by name, message ids) and never writes or reads the release ledger, so deliver_run still refuses the run.
FIND: any way review_drop sends something labelled or implying a pass, omits a non-pass required row, sends bytes other than those hashed, sends when a content-integrity row fails, or lets a review-dropped run be released; any way it leaks the chat id or token. Reply with the JSON verdict; keep the reasoning short; at most 3 findings.

**Panel:** qwen27b, deepseek  |  **Cost:** $0.0153
## Consensus findings (majority of panel agrees)
- **[low] pipeline/telegram.py:411** The forbidden-word regex for PASS is case-sensitive (`r"\bPASS(ED)?\b"` with no `(?i)` flag), while the other two patterns use `(?i)`. A caption or note that contains the lowercase token "pass" or "Pass" used as a verdict (e.g. a clip title "pass: segment 3") would not be caught, allowing PASS-as-verdict wording to reach the approval chat.
  - evidence: `    hits = [m.group(0) for rx in (r"\bPASS(ED)?\b", r"(?i)CANDIDATE FOR APPROVAL", r"(?i)\bapproved\b")
            for m in re.finditer(rx, body)]`
  - fix: Add the inline case-insensitive flag to the first pattern: `r"(?i)\bPASS(ED)?\b"`. This will also match "pass", "Pass", "passed", etc., consistent with the other two patterns.
  - raised by qwen27b:F2; agree: qwen27b, deepseek

## Raised but not agreed
- qwen27b:F1 [medium] The `finally` block writes REVIEW_DROP.json even when a `send()` call raises mid-sequence. If the first video transmits but the second video or the note message fails (e.g. transient network error), the file is created and the run is permanently blocked from review-dropping. The code checks only `os.path.exists(rpath)` on re-entry and does not inspect `rec["status"]`, so there is no programmatic retry path; the operator must manually delete the file, risking a duplicate send of the first video. (agree: 1)
