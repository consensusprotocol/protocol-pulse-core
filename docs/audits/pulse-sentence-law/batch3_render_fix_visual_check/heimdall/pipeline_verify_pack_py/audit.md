# Heimdall audit

**Question:** Protocol Pulse news-video pipeline. Changes: (1) pipeline/transitions.py renamed pulse_transitions.py because render16 puts a legacy folder with its own transitions.py first on sys.path (import shadowing); (2) a contact sheet of the finished video plus a 6-line visual checklist answered by two vision models, any no/missing/unparseable answer = HOLD, added on top of existing gates, never replacing one; (3) fade-out retry made transactional (a moved cut is kept only if the re-prepared clip passes the whole contract, else original cut and clip restored); (4) one function decides whether cuts are machine-placed; (5) Telegram delivery attaches the sheets. Find real bugs: wrong pass/fail decisions, a gate that can pass when it should hold, crashes, lost files, state left inconsistent after a failure. Only state what you can verify from the diff. (this chunk: pipeline/verify_pack.py)

**Panel:** deepseek, qwen27b  |  **Cost:** $0.0171
## Consensus findings (majority of panel agrees)
- **[medium] pipeline/verify_pack.py:0** When `VC.contact_sheet` raises, the code records an error but still calls `VC.ask_panel(sheet, ...)` on the same fixed path. If a stale `qa/contact_sheet_<fmt>.jpg` from a previous run exists, the panel can answer from that stale sheet and return ok=True, producing a V1 PASS for a format whose current contact sheet was never generated (wrong pass decision; the docstring says a missing sheet must be a FAIL).
  - evidence: `        except Exception as e:                          # no sheet = incomplete pack and a failing V1 row
            pack["contact_sheets"][fmt] = {"error": f"{type(e).__name__}: {e}"}
        if not`
  - fix: Skip the panel call (and force V1 FAIL) when `pack["contact_sheets"][fmt]` contains an error / the sheet file was not freshly produced, e.g. `if "error" in pack["contact_sheets"][fmt]: v = {"ok": False, "error": ...}` before calling ask_panel.
  - raised by deepseek:F2; agree: deepseek, qwen27b
- **[medium] pipeline/verify_pack.py:0** The `nos` set-comprehension assumes every `per_model` value is a dict with a `rows` dict whose entries have an `ok` key. An unparseable/malformed panel answer (which the docstring says must become a FAIL, not a crash) that is represented as a non-dict or a dict without `rows`/`ok` raises KeyError/TypeError. This line is outside the try/except, so it aborts `build` after contact sheets have been written but before GATE_REPORT.json is saved, leaving GATE_REPORT.json without the V1 rows and VERIFICATION.json unwritten (inconsistent state).
  - evidence: `        nos = sorted({k for d in (v.get("per_model") or {}).values() for k, r in d["rows"].items() if not r["ok"]})`
  - fix: Guard the traversal, e.g. iterate `(d.get("rows") or {})` and use `r.get("ok")` with a default of False, and treat any malformed model entry as a failing row rather than letting the comprehension raise.
  - raised by deepseek:F3; agree: deepseek, qwen27b

## Raised but not agreed
- deepseek:F1 [high] The pack's `complete` flag never incorporates the new V1 visual-checklist result, so a run whose vision panel answered 'no'/missing/unparseable (V1 row FAIL) can still be marked complete. The V1 gate is written only into GATE_REPORT.json, while VERIFICATION.json's `complete` is computed independently, leaving the two artefacts contradictory (GATE_REPORT FAIL vs complete=True) and allowing a hold-required run to pass. (agree: 1)
- qwen27b:F1 [high] V1 gate can PASS when it should HOLD: the pass/fail decision is solely `v["ok"]`, but the code also computes `nos` (the set of individual checklist rows where `r["ok"]` is False) and uses it only in the error-message string. If `VC.ask_panel` returns `ok=True` while one or more per-model rows have `ok=False` (e.g. `ok` signals 'API call succeeded' rather than 'every answer is yes'), the gate writes PASS even though a 'no' answer exists. The audit requirement is 'any no/missing/unparseable answer = HOLD'. (agree: 1)
- qwen27b:F2 [medium] `pack["complete"]` calls `.get("path")` on the value stored by `VC.contact_sheet`. If that function returns a plain path string (or any non-dict), the expression `(pack["contact_sheets"].get(f) or {}).get("path")` raises `AttributeError: 'str' object has no attribute 'get'`, crashing `build()` after the sheet was successfully generated. The error path stores a dict (`{"error": ...}`), but the success path stores the raw return value of `VC.contact_sheet` with no type guard. (agree: 1)
- qwen27b:F3 [medium] GATE_REPORT.json is loaded once at the top of `build()`, mutated in-memory by `_sheets_and_checklist`, and written back only when `vision=True`. If the `json.dump` write fails (I/O error, disk full), the in-memory `rep` already contains the V1 rows and `pack` is subsequently written to VERIFICATION.json with `contact_sheets`/`visual` data. The two files are left inconsistent: VERIFICATION.json references contact sheets and visual results that GATE_REPORT.json does not record. There is no rollback or atomic-write guard. (agree: 0)

## Added in cross-examination (not voted on)

- deepseek: [medium] GATE_REPORT.json is updated with V1 rows inside _sheets_and_checklist before build writes VERIFICATION.json; if the VERIFICATION.json write fails, GATE_REPORT.json is updated but VERIFICATION.json is not, leaving the two artefacts inconsistent.
