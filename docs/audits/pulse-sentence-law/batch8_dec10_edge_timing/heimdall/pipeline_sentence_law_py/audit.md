## Raised but not agreed
- qwen27b:F1 [critical] NameError: VALLEY_BELOW_SPEECH_DB is referenced in neighbour_clear but never defined. The constants block defines WORD_BELOW_SPEECH_DB = 6.0 (for the 6 dB word-heard threshold) but the valley threshold (speech − 12 dB per the DEC-10 spec) is a separate constant that is missing. Every call to neighbour_clear will raise NameError at runtime, crashing accepted_cut, _accepted_cut_pair, write_lock_cut_table, and gate_g16. (agree: 1)
- qwen27b:F2 [high] Acoustics check is skipped whenever either side is a valley cut. The condition 'not (v["in"] or v["out"])' means that if one side is a 2-frame valley fade and the other is a normal 20/30 ms fade, check_cut_acoustics is never called. The normal side's fade is not verified for clicks or breath artifacts, so a bad cut on the non-valley side can pass. The old code always called check_cut_acoustics on the pair. (agree: 1)
- qwen27b:F3 [medium] cut_candidates now always returns a non-empty list by falling back to the plan's target point when no grid point passes the acoustics check. Combined with F2 (acoustics check skipped for valley cuts), a cut that previously would have been rejected because no point in the range passed cut_accept can now pass as a 'valley' cut with only neighbour_clear as the gate. This converts must-fail cases (no valid cut point) into potential passes. (agree: 1)
- qwen27b:F4 [medium] TAIL_MIN_S is now 0.000, making the tail check in gate_g17_prepared vacuous: ht["tail_ms"] >= 0 is always true for any non-negative tail. A clip whose last word is clipped (0 ms tail) passes this gate. While G17b (85 % word completeness) is a separate check, the timing gate no longer provides any independent protection against a clipped last word. (agree: 1)

## Added in cross-examination (not voted on)
- qwen27b: [high] In the mixed-valley case (one side valley, one side normal), the normal side's fade duration is hard-coded to 0.020/0.030 s in accepted_cut, but check_cut_acoustics is never called for that side (see F2). More critically, the neighbour_clear fade for the normal side uses the correct 20/30 ms, yet the acoustics verification that would catch a click or breath at that 20/30 ms fade is entirely absent. This means a prepared clip can have an audible click at the non-valley cut edge and still pass both accepted_cut and gate_g16, because neither function re-verifies the acoustics of the normal-side fade when the other side is a valley.
