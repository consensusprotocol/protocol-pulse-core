### Q2 — PROBABILITY CALIBRATION
**The base probabilities (28%, 18%, 4%, 32%, 18%) were described as "calibrated against historical cycles." What is the most rigorous defensible methodology for setting these priors given only 4-5 historical Bitcoin cycles? Be specific about the statistical approach.**

**Methodology for Setting Priors with Limited Data:**
Given the scarcity of historical Bitcoin cycles (4-5 data points), a Bayesian approach with a conjugate prior is the most defensible and rigorous method for calibrating base probabilities. The foundation document mentions using a beta distribution, which is appropriate due to its natural bounding between [0,1] and ability to model uncertainty. Here’s a detailed methodology:

1. **Define Historical Outcomes:**  
   For each of the 4-5 historical cycles (e.g., 2013, 2017, 2020-21, 2024), classify which scenario(s) "won" based on post-hoc analysis of market behavior, regulatory events, and network metrics. Allow for partial wins if multiple scenarios partially manifested (e.g., Institutional Adoption and Macro Liquidity Expansion could overlap in 2020-21). This results in a fractional "success count" for each scenario per cycle.

2. **Set Weak Informative Priors:**  
   Start with a weak uniform prior for each scenario using a Beta(1,1) distribution, which assumes no prior knowledge and is equivalent to a 50% probability with maximum uncertainty. This avoids overconfidence given the small sample size.

3. **Update with Historical Data (Bayesian Updating):**  
   For each scenario, count the number of cycles where it "won" (successes) and did not win (failures). Update the Beta prior as follows:  
   - New Alpha = 1 + number of successes  
   - New Beta = 1 + number of failures  
   For example, if Scenario 1 (Institutional Adoption) "won" in 2 out of 5 cycles, the posterior is Beta(1+2, 1+3) = Beta(3,4), with a mean probability of 3/(3+4) ≈ 42.9%. Adjust for partial wins by weighting successes (e.g., a 0.5 win counts as 0.5 success).

4. **Adjust for Temporal Relevance:**  
   Weight more recent cycles more heavily to account for evolving market dynamics (e.g., institutional involvement is more relevant post-2020). Apply an exponential decay factor to older cycles (e.g., weight = 0.8^(cycle age in years)), and normalize weights before updating the Beta parameters.

5. **Compute Posterior Means as Base Probabilities:**  
   Use the posterior mean of each Beta distribution as the base probability for each scenario. This naturally bounds probabilities between 0 and 1 and reflects historical frequency while incorporating uncertainty from the small sample size.

6. **Validate with Bootstrapping:**  
   Given the small number of cycles, perform a bootstrap resampling of the historical outcomes (with replacement, 10,000 iterations) to estimate the variability of the posterior means. Report the median posterior mean as the final base probability to mitigate outlier effects.

7. **Normalize if Necessary:**  
   If the sum of posterior means across scenarios deviates significantly from 100% due to overlapping wins, normalize them proportionally while preserving relative magnitudes.

**Rationale:**  
This approach is defensible because the Beta distribution is a conjugate prior for binomial outcomes (scenario win/loss), ensuring computational simplicity and interpretability. The weak prior avoids overconfidence, and temporal weighting accounts for Bitcoin’s evolving ecosystem. Bootstrapping addresses the small sample size by quantifying uncertainty. This methodology aligns with institutional risk modeling practices where data scarcity necessitates Bayesian methods with careful prior selection.

### Q3 — MONTE CARLO CORRECTNESS
**Review the Monte Carlo process. The spec says 10,000 iterations with ±20% signal jitter to produce confidence intervals. Is ±20% the right jitter amount? What distribution should the jitter follow (uniform? normal? beta?)? Write the exact numpy code for the correct simulation.**

**Analysis of Jitter Amount and Distribution:**
- **Is ±20% the right jitter amount?**  
  No, ±20% is likely too narrow and arbitrary. The jitter should reflect the empirical uncertainty in signal confirmation strength, which varies by signal type (e.g., ETF inflows have different measurement error than regulatory threat levels). A better approach is to estimate jitter ranges from historical signal volatility or expert judgment. For instance, hard data signals (e.g., ETF inflows, hashrate) might have ±10-15% uncertainty due to data precision, while softer signals (e.g., regulatory threat) might have ±30-50% due to subjectivity. As a starting point, I recommend a default jitter of ±30% to capture broader uncertainty, adjusted per signal based on data quality metadata in SentinelState.

- **What distribution should the jitter follow?**  
  The jitter should follow a **normal distribution** centered at 0 with a standard deviation derived from the jitter range (e.g., for ±30%, σ ≈ 15% to keep ~95% of samples within bounds). Normal distribution is appropriate because signal measurement errors often aggregate as normally distributed noise (Central Limit Theorem), and it avoids the hard cutoffs of uniform distribution or the asymmetry of beta distribution (which is better for bounded probabilities, not additive noise). Normal also allows occasional extreme deviations, reflecting real-world signal outliers.

**Exact Numpy Code for Monte Carlo Simulation:**
```python
import numpy as np

def run_monte_carlo_simulation(scenarios, num_iterations=10000, jitter_std=0.15):
    """
    Run Monte Carlo simulation to compute confidence intervals for scenario probabilities.
    :param scenarios: List of dicts with scenario data (base_probability, signals)
    :param num_iterations: Number of Monte Carlo iterations
    :param jitter_std: Standard deviation for normal jitter (15% ≈ ±30% range at 2σ)
    :return: Dict with p10, p50, p90 for each scenario
    """
    num_scenarios = len(scenarios)
    probabilities_over_iterations = np.zeros((num_iterations, num_scenarios))
    
    for i in range(num_iterations):
        # Copy base probabilities for this iteration
        iter_probs = np.array([s['base_probability'] for s in scenarios])
        
        # Apply jitter to signal confirmations for each scenario
        for s_idx, scenario in enumerate(scenarios):
            for signal in scenario.get('signals', []):
                if signal.get('confirmed', False):
                    # Jitter the probability delta with normal distribution
                    jitter = np.random.normal(loc=0, scale=jitter_std * signal['probability_delta'])
                    iter_probs[s_idx] += signal['probability_delta'] + jitter
        
        # Apply contradiction penalties (simplified here, use full matrix in practice)
        for s_idx, scenario in enumerate(scenarios):
            for t_idx, other in enumerate(scenarios):
                if s_idx != t_idx and 'contradiction_penalty' in scenario:
                    if iter_probs[t_idx] > 40:  # Example threshold for penalty
                        iter_probs[s_idx] -= scenario['contradiction_penalty'].get(other['id'], 0)
        
        # Clip probabilities to [1%, 95%]
        iter_probs = np.clip(iter_probs, 1, 95)
        
        # Normalize to sum to 100%
        total = np.sum(iter_probs)
        if total > 0:
            iter_probs = (iter_probs / total) * 100
        
        probabilities_over_iterations[i, :] = iter_probs
    
    # Compute confidence intervals (p10, p50, p90) for each scenario
    confidence_intervals = {}
    for s_idx, scenario in enumerate(scenarios):
        probs = probabilities_over_iterations[:, s_idx]
        confidence_intervals[scenario['id']] = {
            'p10': np.percentile(probs, 10),
            'p50': np.percentile(probs, 50),
            'p90': np.percentile(probs, 90)
        }
    
    return confidence_intervals

# Example usage
scenarios = [
    {'id': 'S1', 'base_probability': 28.0, 'signals': [{'probability_delta': 5.0, 'confirmed': True}]},
    # ... other scenarios
]
results = run_monte_carlo_simulation(scenarios)
print(results)
```

**Rationale:**  
This code uses a normal distribution for jitter with a standard deviation of 15% (covering ±30% at 2σ), which balances realism and computational stability. It applies jitter per signal, respects contradiction penalties, clips probabilities, and normalizes them per iteration. The 10,000 iterations are sufficient for stable percentiles (p10, p50, p90), aligning with institutional Monte Carlo practices for risk modeling.
