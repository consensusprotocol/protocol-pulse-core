## Components
- `pipeline/transcript_store.py` — canonical cache `data/editorial/transcripts/<video_id>/` (gitignored). `meta.json` (video_id, canonical_url, channel_id, channel_name, exact_title, published_at from the channel RSS, duration, live_status, description, caption availability) and immutable `transcript.<method>.json` records (transcript_method, transcript_model, timestamped segments, transcript_sha256 over the segments, media_sha256 when audio was downloaded). Records are write-once (FileExistsError on overwrite) and hash-verified on every read. Chunks: deterministic 30-60 s windows, id `<video_id>:<start_ms>-<end_ms>`, each carrying the full source identity + transcript_sha256.
- Acquisition policy: cached -> native captions (manual > auto en-orig > auto en) with backoff -> faster-whisper on GPU0 (distil-large-v3, batched). A caption HTTP 429 is a path switch and opens a 30-min caption circuit breaker; never "no transcript". VODs > 3 h and live streams are skipped and logged. Clip-quality candidates get one extra immutable `whisper_words` record (word timestamps -> sentence segments).
- `pipeline/transcript_ingest.py` — background ingestion of the editorial universe (every enabled registry channel with a channel_id; layout approval irrelevant). Single instance (flock), GPU0 only, Whisper deferred while a production render runs, bounded audio budget. Cron every 30 min.
- `pipeline/story_semantics.py` — BAAI/bge-base-en-v1.5 (pinned revision a5beb1e3) embeddings on GPU0; gemma3:27b via the shared Ollama on :11434 only after proving from the live process environment (CUDA_VISIBLE_DEVICES=0) and nvidia-smi that it is GPU0-only (the :11435 instance is pinned to quarantined GPU1 and never used). Story-query derivation (underlying event, entities+aliases, action, object, date context, concepts, must-not-confuse-with, Bitcoin relevance, importance); per-video SAME_EVENT / RELATED_DIFFERENT_EVENT / UNRELATED adjudication whose evidence quote must appear verbatim in the supplied attributed chunks, otherwise it does not count; emergent cross-channel clusters labelled by the LLM; clip ratings.
- `pipeline/editorial_select.py` — candidates = all story-engine items + emergent transcript clusters. Three separate scores in order: STORY IMPORTANCE (LLM importance, Bitcoin relevance >= 3, recency; engine score recorded and flagged when its GPT-4o legs are unavailable), CROSS-SOURCE COVERAGE (independent channels with verified SAME_EVENT evidence, >= 2), CLIP QUALITY (sentence-bounded passages from layout-approved evidence videos only, LLM-rated; hook >= 4, clips >= 3.5, >= 2 layout-approved channels). Every candidate is evaluated; HOLD only if none is producible. Outputs TOPIC_SELECTION.json (universe, every candidate, queries, verdicts with chunk ids/timestamps/urls/quotes, decisions), passages.json (select-stage contract, full-video seconds), sources.json.
- `pipeline/run_fresh.py` — `topic/discover/rank` replaced by `editorial`; everything from `select` on unchanged.
- `pipeline/channels.json` — channel_id added for Simply Bitcoin (handle corrected @SimplyBitcoinTV -> @SimplyBitcoin), What Bitcoin Did, Bitcoin Audible, Bitcoin Mechanic, Real Vision, Clark Moody, Bloomberg Television, Kitco NEWS (exact name/handle match + live RSS). 10 still missing (ambiguous searches): Ansel Lindner, BTC Inc, Bitcoin Magazine Pro, Casa, The Investors Podcast Network, Bitcoin Magazine Clips, Fountain, Gemini, HIVE Digital, MARA Holdings.

## Known limitations (not hidden)
- Story-engine GPT-4o clustering/scoring remains unavailable (OpenAI 429; xAI key absent); importance uses local gemma3:27b ratings and records the engine score as degraded, not equivalent.
- Emergent clusters use average-linkage cosine clustering (threshold 0.22) over 30-60 s chunks; evergreen themes are filtered by the LLM label, not by the clustering.
- Ollama on :11434 is shared with other cron jobs; model swaps can add latency.
- `scripts/tmux_cleanup.sh` kills quiet tmux sessions every 2 h unless the name matches its keep-list; long runs must use a `pipeline*` session name.
