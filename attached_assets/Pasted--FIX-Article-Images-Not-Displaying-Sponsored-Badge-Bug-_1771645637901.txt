# FIX: Article Images Not Displaying + Sponsored Badge Bug

## CONTEXT: How This Project Works

- Articles are stored in a PostgreSQL database (SQLAlchemy model `Article` in `models.py`) with a field `header_image_url`
- Images are generated by `services/image_service.py` using OpenAI's GPT-4o image generation (model: `gpt-image-1`, fallback: `dall-e-3`). **DO NOT modify this file or change the model.**
- Generated images are saved locally to `static/images/headers/` as JPEG files and the path (e.g. `/static/images/headers/header_Something_20260220_085334.jpg`) is stored in `article.header_image_url`
- There are TWO separate code paths that generate articles: `services/article_automation.py` and `services/content_engine.py`
- The routes in `routes.py` build a dict called `article_image_urls` that maps article IDs to image URLs, which templates then use
- Templates use `article_image_urls.get(article.id, default_header_url)` to display images

## BUG 1: `article_image_urls` dict falls back to stale image pool

**Location**: `routes.py` — there are at least 2-3 places where `article_image_urls` is built:
- Index route (around line 345)
- Articles route (around line 1226)  
- Possibly a news route (around line 3338) that has a HARDCODED Unsplash URL

**Problem**: When `article.header_image_url` is empty OR when the route falls back, it calls `get_article_header_url()` from `services/content_generator.py`. That function picks from a static `ARTICLE_HEADER_IMAGE_POOL` of ~10 old images using a hash. This means even when the DB has a valid new image path, the fallback pool can override it, or old cached page renders show stale images.

**Fix**:
1. In EVERY route that builds `article_image_urls`, ensure this exact logic:
```python
import os, time
article_image_urls = {}
for a in all_articles_on_page:
    url = (getattr(a, "header_image_url", None) or "").strip()
    if url and url != "/static/images/default-header.png":
        # Add cache-buster using file modification time
        filepath = url.lstrip("/")
        if os.path.exists(filepath):
            mtime = int(os.path.getmtime(filepath))
            url = f"{url}?v={mtime}"
    else:
        url = "/static/images/default-header.png"
    article_image_urls[a.id] = url
```
2. Remove or replace ANY call to `get_article_header_url()` in routes.py with the above logic. That function and `ARTICLE_HEADER_IMAGE_POOL` in `services/content_generator.py` are legacy and should NOT be used for image selection.
3. Find the hardcoded Unsplash URL around line 3338 of routes.py (`"https://images.unsplash.com/..."`) and replace it with `"/static/images/default-header.png"`
4. Search routes.py for ALL occurrences of `default_header_url` and make sure it's set to `"/static/images/default-header.png"` everywhere, not an Unsplash URL.
